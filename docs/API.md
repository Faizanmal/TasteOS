# TasteOS API

OpenAPI UI: `GET /docs` (generated by FastAPI).

Base URL (local): `http://localhost:8000`

**Phase status:** Core API + Group Concierge engine implemented. Live retrieval uses the verified Qloo client when `TASTEOS_MODE=live`.

## Mode

| Mode | Behavior |
| --- | --- |
| `demo` | Curated labeled dataset (`tasteos_demo_dataset`). Never presented as live Qloo. |
| `live` | Calls Qloo `GET /search` and `GET /v2/insights` with `X-Api-Key`. |

`GET /api/v1/mode` returns the active mode and whether a Qloo key is configured (boolean only — never the key).

---

## Qloo integration (verified)

Client: `apps/api/app/services/qloo/client.py` — Concierge **reuses** this client via `CulturalCandidateRetriever`; it does not re-implement Insights/Search.

| Capability | Method + path |
| --- | --- |
| Entity search | `GET /search` |
| Insights | `GET /v2/insights` (query string only) |

Affinity is copied **only** when present. `app_rank_score` is TasteOS negotiation (`tasteos_negotiation_v1`) — never a Qloo consensus score.

### Group Concierge (Phase 4)

| Method | Path | Notes |
| --- | --- | --- |
| `POST` | `/api/v1/concierge/plan` | Full pipeline → proposed outing |
| `GET` | `/api/v1/concierge/plan/{plan_id}` | Persisted plan payload |
| `POST` | `/api/v1/concierge/plan/{plan_id}/reject?entity_id=` | Hard-exclude + regenerate |

#### Request (`ConciergePlanRequest`)

| Field | Notes |
| --- | --- |
| `profile_ids` | 1–8 profile ids (demo or created) |
| `experience` | `evening_out` \| `dinner` \| `drinks` \| `culture_night` |
| `target_domain` | Insights filter type (default `urn:entity:place`) |
| `location_query` | Optional location constraint |
| `budget` | `any` \| `casual` \| `mid` \| `upscale` |
| `exclusions` | Extra hard entity-id exclusions |
| `rejected_entity_ids` | Prior rejections (also set by reject endpoint) |
| `alternatives_count` | 0–10 ranked alternatives (default 3) |
| `take` | Candidate pool size hint |

#### Response (`ConciergePlanResponse`)

| Field | Notes |
| --- | --- |
| `primary` | Top `CandidateOut` with `participant_matches`, `evidence_refs`, `app_rank_score`, optional `qloo_affinity` |
| `alternatives` | Next-best candidates |
| `itinerary` | Proposed stops (`is_proposed: true`); **not** bookings |
| `tradeoffs` | Group trade-off narrative |
| `selection_rationale` | Why primary won (formula inputs + evidence refs) |
| `disclaimer` | Explicit non-booking statement |
| `reconciliation` | Per-participant statuses for the primary |
| `pipeline` | Audit stages: resolve → retrieve → constrain → negotiate → provenance → compose → explain |
| `limitations` | Unknowns, demo labels, booking disclaimer |
| `rejected_entity_ids` | Accumulated hard rejections |

Scoring formula: see [ARCHITECTURE.md](ARCHITECTURE.md) (`tasteos_negotiation_v1`).

## Error shape

```json
{ "error": { "code": "…", "message": "…", "details": {} } }
```

| Code | Typical status |
| --- | --- |
| `request_validation` | 422 |
| `validation` | 400 (e.g. empty candidates, missing profile) |
| `forbidden` | 403 |
| `qloo_upstream` | 401–504 |
| `database_unavailable` | 503 |

## Example: Group Concierge plan (demo)

```bash
curl -s http://localhost:8000/api/v1/concierge/plan \
  -H "Content-Type: application/json" \
  -d '{
    "profile_ids": [
      "demo-profile-maya",
      "demo-profile-jordan",
      "demo-profile-sam"
    ],
    "target_domain": "urn:entity:place",
    "location_query": "New York",
    "experience": "evening_out",
    "alternatives_count": 3,
    "take": 6
  }'
```

Reject and regenerate:

```bash
curl -s -X POST \
  "http://localhost:8000/api/v1/concierge/plan/{plan_id}/reject?entity_id={entity_id}"
```

## Phase 5 — Frontend (implemented)

Next.js app (`apps/web`) wires the full Concierge journey (no browser Qloo keys):

| Screen | Route |
| --- | --- |
| Landing | `/` |
| Group setup (+ create profile) | `/concierge` |
| Preference editor | `/concierge/edit` |
| Taste comparison + overlap | `/concierge/compare` |
| Results / itinerary / reject | `/concierge/results` |
| Developer API overview | `/developers` |

Client: `apps/web/src/lib/api.ts` · env: `NEXT_PUBLIC_API_BASE_URL`

1. **Bootstrap:** `GET /api/v1/mode`, `GET /api/v1/profiles/demo`, optional `POST /api/v1/profiles`.
2. **Plan:** `POST /api/v1/concierge/plan` with selected `profile_ids` + `experience` + constraints.
3. **Display:** show `disclaimer`; separate **retrieved** (`source`, `qloo_affinity`, `evidence_refs`) from **TasteOS** (`app_rank_score`, `selection_rationale`, `tradeoffs`).
4. **Reject:** `POST …/reject?entity_id=` then replace the plan; primary must change.
5. **Badges:** demo vs live from `mode` / `primary.source` — never imply demo is live Qloo.
6. **Copy:** itinerary is proposed only; do not claim reservations.
